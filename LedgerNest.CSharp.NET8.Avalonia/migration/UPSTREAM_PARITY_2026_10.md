### Company workspaces and backup ownership batch

- A device-level, atomically written company registry adopts the existing database in place. Additional companies receive separate initialized SQLite databases; company identity is checked before dependent ViewModels load. Registry mutations serialize across application instances and validate names, duplicate entries and configuration. No business table or schema change is needed; identity uses the existing settings table.
- AXAML company management and a sidebar selector support create, rename, switch and delete. Management commands require a current Admin session and the existing business-write entitlement. Switching prepares a fresh dependency container and signed-out ViewModel, invalidates the previous session, commits the active company and replaces the window. Presentation failures restore the active registry entry while leaving the old session signed out. Stale workspaces lose menu/action access if another instance switches companies.
- Existing database setup remains the first-run path. An established registry is authoritative on subsequent startup, including when the legacy profile file is absent. Startup failures display an AXAML recovery window. SQLite backup composition now passes the actual database path rather than its connection string; database-profile writes preserve the prior file on failure.
- Backup dialogs default to separate company-ID directories and safe company-name/ID filenames. SQLite and JSON restore validate ownership before changing the destination. Legacy identity-free backups are accepted only by the adopted original company and stamped during restore; other companies reject them. Company-specific history remains in each company database. An optional IBAN field loads compatibly from old bank accounts, persists and prints through the common PDF renderer.
- Intentional safety difference from upstream: Delete removes the company from the registry and archives its profile but retains its database for recovery. It never drops an externally configured database or deletes the adopted original file. The active and last company cannot be deleted. Users may choose another backup destination in the existing native file picker.
